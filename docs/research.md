### 1.2 探针

`scripts/probe.py` 在 56 条留出 episode 上每 40 帧取一帧，共 4610 帧。同一帧上，基线和各扰动共用一份 flow 噪声，统计前 8 步执行动作的关节部分。

| 指标 | 定义 | 读法 |
|---|---|---|
| 换画面增益 `gain/swap_views` | 换入同变体另一条留出 episode、相同进度的四路画面，动作变化在两条演示动作差上的投影比 | 1 完全跟画面，0 忽略画面 |
| 恢复率 `recovery/<d>` | 关节状态加偏移 δ 后，第 8 步动作的修正比例 1 − ⟨A_probe − A_base, δ⟩ / \|δ\|² | 0 原样带进输出，1 完全拉回 |
| 敏感度 `sens/<probe>` | 平均 \|A_probe − A_base\|，探针有外部画面平移、相机置灰、换指令 | 输出是否依赖该输入 |

### 1.3 R1 学到了什么 [M]

R1 25000 步（`runs/probe/r1-25000/`）：

| 探针 | 动作变化（mrad） |
|---|---|
| 基线对演示的误差 | 0.79 |
| 腕部 / 外部相机置灰 | 2.41 / 0.70 |
| 外部画面平移 8 / 16 px | 0.10 / 0.12，与采样底噪同量级 |
| 换成兄弟变体的指令 | 0.25 |
| 关节状态偏移 4 / 8 / 16 mrad | 4.02 / 7.99 / 15.96，恢复率 0.002 / 0.004 / 0.004 |
| 换画面增益 | 宏平均 0.33；Task1–3 0.37–0.46，Task4 0.15–0.23，Task5 0.20–0.25 |

- R1 是速度策略。标签是"演示指令 − 测量状态"，主要由速度和跟踪滞后决定，而模型看绝对位置的精度只有 2.6–7.2 mrad（§2.1）。输出增量与位置无关，状态偏多少，绝对指令就跟着偏多少。
- 外部视角基本不参与定位：演示里塔几乎不动，外部画面没有位置方差；随机裁剪和旋转增强又专门训练了对平移不变（§2.3）。
- 越接近定时回放的任务，画面增益越低，Task4 最低。

文献对应 [P]：主因是不可辨识，策略的空间有效范围贴着演示的物体位置分布（DemoGen [2502.16932](https://arxiv.org/abs/2502.16932)、ALT [2505.05787](https://arxiv.org/abs/2505.05787)），Task4 是极端情形；次因是本体捷径，状态压制视觉（State-free Policy [2509.18644](https://arxiv.org/abs/2509.18644)、GAP [2602.12032](https://arxiv.org/abs/2602.12032)）。物体稍一偏移 π0 仍奔向旧位置（LIBERO-PRO [2510.03827](https://arxiv.org/abs/2510.03827)、AFI [2512.07472](https://arxiv.org/abs/2512.07472)、Breaking Lock-In [2604.23121](https://arxiv.org/abs/2604.23121)），这是 Shifted assembly 的预期失败方式。腕部视角利于分布外泛化（Hsu 等 [2203.12677](https://arxiv.org/abs/2203.12677)），与腕部置灰的影响是外部的 3 倍一致。

### 1.4 R2、R3 的离线变化 [M]

| 试点 | 改动 | mae8 | 恢复率 4 / 8 / 16 mrad |
|---|---|---|---|
| R1 | | 0.819 | 0.002 / 0.004 / 0.004 |
| A | 只换官方指令 | 0.810 | 0.002 / 0.003 / 0.003 |
| B | A + 高斯状态噪声 σ = 1 档 | 1.085 | 0.376 / 0.291 / 0.126 |

| D | A + 整数档 DART K=2 | 1.062 | 0.438 / 0.378 / 0.194 |

换官方指令没有代价。状态噪声 2000 步内就能教会纠偏，代价是干净输入误差上升 32%。D 的三个尺度恢复率都高于 B，误差略低；E 没有超过 D。R2 因此用整数档 DART、不用旁路（机制见 §2.2，决策见 [recipe.md](recipe.md) §8）。

快照指标表在 [evaluation.md](evaluation.md) §3.2。读法：

- R2 从 27500 到 40000 步，mae8（1.027 → 0.673）、恢复率和换画面增益都单调变好，32500 步回到 R1 水平。噪声的误差代价被余弦冷却抵消。
- 外部平移敏感度从 0.118 升到 0.171。官方相机标定固定，评测里没有这种平移，这只说明模型更多地用上了外部视角。
- 对照 r2g 只多保留外部几何增强：每个同步数快照的恢复率相差不超过 0.006，40000 步 mae8 0.690，外部平移敏感度一直在 0.123–0.129。R2 的收益来自 DART 和冷却；关增强无害、略好。
- R2 与 r2g 的 40000 步等权平均（`runs/eval/soup-40000/`）mae8 0.700，比两者都差，不用。
- r3a 加接触段加权，接触段误差和恢复率略好。r3b 再混入 40% 渲染版 DART，每个变体都退步（task4-3 mae8 0.460 → 0.761），大偏移的恢复好得多，外部视角敏感度是 r2 的 7 倍。对照 r3d 只用 DART 里未扰动的帧，离线各项与 r3a 相同（mae8 0.679，敏感度 0.180）。所以 r3b 的离线变化全部来自扰动帧的纠偏标签；见过本地渲染画面本身不改变录制图像上的行为（§5.2、§7）。

## 2. 状态通道与空间泛化

### 2.1 状态分辨率 [M]

openpi 的 π0.5 用 `np.digitize` 把归一化状态分成 256 档写进 prompt（openpi @215abfb `models/tokenizer.py`），动作专家没有连续状态输入。[q01, q99] 映射到 [−1, 1] 后，14 个臂关节每档 2.6–7.2 mrad，比动作误差粗 3–9 倍；归一化后 3.3%（训练）和 3.4%（验证）的值落在 [−1, 1] 外而饱和（`runs/audit/norm_overflow.txt`）。推理数值精度不是瓶颈，见 [throughput.md](throughput.md) §7.1。[2608.03052](https://arxiv.org/abs/2608.03052) 发现离散状态 prompt 是唯一显著优于无状态的接口，但没有测空间泛化和状态噪声 [P]。

### 2.2 整数档 DART 与连续状态旁路

干净数据里，状态的档内残差可以从画面和时序推出来。加连续噪声 ε 后，标签变成"演示 − (q + ε)"，模型只看得到 q + ε 落在哪一档，标签里多出一项看不见的抖动，量级 bin/√12 ≈ 0.8–2.1 mrad，与动作误差同量级 [H]。

整数档 DART（`--state-noise-bins K`）每个关节取 [−K, K] 内均匀的整数 k，扰动恰好 k 个档宽：档内位置不变，token 恰好移 k 档，标签偏移精确等于 −k × 档宽。会移进或停在饱和区的关节本次不扰动（`src/jenga/dataset.py`，测试 `tests/test_policy.py`、`tests/test_dataset.py`）。DART 原文 [1703.09327](https://arxiv.org/abs/1703.09327) 在采集时注入噪声，画面与状态一致；这里只扰动状态，噪声必须小到画面上看不出来。1–2 档对应末端约 1.3–7 mm [H]。画面与状态一致的版本见 §7。

连续状态旁路 `Pi0Config.continuous_state`（`patches/openpi-tower.patch`；训练入口已删除）把 32 维归一化状态和档内小数位置经零初始化的 `state_proj` 加到每个动作 token 上，离散 token 不变，第 0 步与原模型逐位相同（`tests/test_openpi_extensions.py`）。试点 E 没有超过 D，不用。

### 2.3 外部视角几何增强

openpi 默认对外部视图做 `RandomCrop(95%) → Resize → Rotate(±5°)`，在 224² 上相当于最多约 ±6 px 平移，与 15 mm 积木平移在画面里的 6–12 px 同量级。它训练的是画面平移时动作不变，适合相机会动的场景；TOWER 的相机标定固定 [P]。从 R2 起关掉（颜色抖动保留）。依据是 r2g 对照（§1.4）：保留时外部视角敏感度一直压在 0.13 mrad 以下，其余指标相当。

### 2.4 测试期参考系变换（已否决）

结论：闭环里有害，服务不再应用。离线验证和协议回放都显示它无害或有益，所以曾默认开启；布局偏移下的本地闭环（本节末）推翻了这一点。布局估计器 `jenga.offset` 留在仓库里，离线验证和测试还在用。

鲁棒 release 的 10 个 case 里有 3 个与位姿有关 [P]：Shifted assembly（可移动积木整体每轴平移最多 15 mm、偏航最多 10°），Irregular layers（各层独立最多 8 mm、5°），以及两者组合。官方说明底座、桌面、机器人、相机标定和目的锚点都固定，只随机化可移动积木和光照 [P]。

做法：从外部相机估计可移动积木的位移，把测量状态变换到规范布局下的虚拟状态再交给策略，输出再变换回真实坐标。腕部画面在虚拟坐标系下与训练一致，唯一不一致的外部视角恰好是模型不怎么用的输入。State-free Policy 的 "state hack" 是它的一维特例：π0 换桌高后 0/30，只把状态平移一个高度差就恢复到 30/30 [P]。演示生成、等变策略、3D 重渲染在冻结前都不可行（固定透视相机下物体的 SE(2) 运动不对应整图刚体变换）；AFI 在 π0/π0.5 上平均 +23.5%，说明测试期干预对 VLA 有效 [P]。

实现：`src/jenga/offset.py`（位移估计）、`src/jenga/warp.py`（形变与 `FrameTransform`）、`src/jenga/kinematics.py`（FK/IK），离线验证 `scripts/validate_warp.py`，测试 `tests/test_{kinematics,offset,warp}.py`。`FrameTransform` 现在只剩离线验证在用。

工位几何 [M]：相机内参取自 HDF5，外参取自 station JSON，首帧积木轮廓与木色掩码 IoU 0.90–0.95（`configs/cameras.json`，`runs/spatial/calib_check.txt`）。在可移动积木处，1 mm 约合 0.3–0.8 px。FK 用 48 个参数拟合 AgileX Nero（本地没有 URDF），留出集位置误差最大 0.007 mm（`configs/nero_kinematics.json`）。手中积木中心距 eef 约 0.2 m，这个工具点必须一起建模：忽略它时臂基座拟合残差为 4.7 / 1.1 mm，建模后为 0.44 / 0.69 mm。关节限位未知。

算法：

1. 位移估计。episode 开始时机器人在回家位，`OffsetEstimator` 从两路外部相机估计刚体位移 T = (dx, dy, dψ)。先做逐通道光度归一化，再按两项打分：名义布局轮廓与木色掩码的相关，加沿可见棱的灰度梯度（边缘项）；饱和像素不计分。扣除每变体的系统偏差，置信度低于阈值时退回恒等变换。
2. 门控 `gate_offset`。|x| ≤ τ 置 0，τ < |x| ≤ 2τ 取 2(|x| − τ)，更大时原样保留。τ 按变体取训练 split 名义首帧上的最大估计误差：平移 1.0–3.2 mm，偏航 0.53–2.1°；搜索区饱和像素超过 2% 时偏航阈值至少 4°。10 个变体都保留偏航：只修平移时积木角点误差 p95 为 18–25 mm，加上偏航后为 2.5–5.1 mm。
3. 形变作用在工具点的水平坐标上：W(x) = c + Rz(w·dψ)(x − c) + w·d，c 是可移动积木中心，w 是 smoothstep 权重，r_in 内为 1，r_out 外为 0。过渡带按演示几何确定（`warp.py` 的 `VARIANT_PARAMS`）：Task1 0.070 → 0.295 m，Task2 0.035 → 0.340，Task3 0.035 → 0.220，Task4 0.175 → 0.345，Task5 0.035 → 0.222。目的地都在 r_out 外。
4. 观测侧 `observe`：q_real → FK → W⁻¹ → IK → q_virtual，作为状态输入，图像原样输入。动作侧 `command`：q_virtual → FK → W → IK → q_real，再做 IK 零空间修正。夹爪不变换。
5. 7 自由度冗余在任务空间里定不下来，`observe` 以最近一次下发的（虚拟，真实）指令对为锚。跟踪准确时，策略看到的始终是名义轨迹。

离线验证 [M]（`runs/spatial/validate/`）。合成位移取 15 mm / 10° 的四个角点，角点误差指可移动积木各角水平位置的最大误差。

协议回放里的开局估计时延和开关对比见 [evaluation.md](evaluation.md) §2.2。

估计器的局限：

- Irregular layers 各层偏移不同，单个刚体 T 对不齐；可以按层分段，但单层露出的像素少、遮挡多。
- 估计误差约 1–2 mm，直接变成轨迹误差。
- 增益 2 时受光面饱和，名义平移误差 p95 升到约 2.1–2.3 mm，偏航误差靠放宽的门控挡住。
- 假设首帧手臂在回家位。
- 偏航大时可能触及关节限位；Task4 在 −10° 角点下推杆满伸也够不到。

## 3. Chunk 后处理 [M]

flow 采样在 chunk 内部留下与任务无关的高频抖动，二阶差分约 4e-4 rad，是演示的 11–28 倍（`runs/audit/roughness_p22500.txt`），chunk 边界处还有跳变。`src/jenga/stitching.py::ChunkFader` 先对关节列做 Savitzky–Golay 平滑（二阶，夹爪不平滑），再把新 chunk 的前 n 步与上一 chunk 对同一帧的预测线性混合。默认 SG9 加淡入 2 步，服务也用这个。

R1 25000 离线 chunk 上实际执行的命令流（K=8，56 条留出 episode，`runs/eval/r1-25000/stitch.json`，`scripts/stitch.py`）：

| 规则 | mae（mrad） | 边界跳变 p95（mrad） | 二阶差分（1e-4 rad） |
|---|---|---|---|
| 不处理 | 0.819 | 19.86 | 5.57 |
| 淡入 2 步 | 0.889 | 13.75 | 3.80 |
| SG9 | 0.800 | 19.79 | 3.35 |
| SG9 + 淡入 2 步（默认） | 0.870 | 13.78 | 1.66 |
| SG9 + 淡入 4 步 | 0.947 | 13.40 | 1.30 |
| 演示 | 0 | 13.33 | 0.27 |

- 淡入 2 步就把边界跳变压到演示水平，再多只增加误差。SG9 单用不增加误差，和淡入叠加后二阶差分降到约 1/3。r2-40000 用默认规则时执行误差 0.703 mrad，跳变 p95 13.4 mrad（`runs/eval/r2-40000/stitch.json`）。
- 否决：把已执行命令作为左侧上下文一起平滑（mae 0.893 mrad，二阶差分 2.09e-4，都更差）；时间集成，即混入更旧的计划（R1 12.5k 上 mae 2.11 mrad、跳变 25.6 mrad）。
- 这是开环评测。淡入让新观测的作用推迟约 2 帧，接触段的影响没有单独在闭环里测。

## 4. 本地闭环仿真

官方评测一个 episode 要几十分钟，给不了闭环迭代；相机倒置、task1-2 起点不同这类问题只有闭环才会暴露。本地闭环用来排序候选和定位失败，成绩以组织方评测为准。协议和命令见 [evaluation.md](evaluation.md) §4。

### 4.1 组成

- 物理：Isaac Sim 5.1 PhysX，只加载物理，不加载渲染器（`sim/physics_only.kit`、`sim/scene.py`、`sim/physics_worker.py`，入口 `sim/isaac.sh`）。工位 USDZ 的 sha256 与官方一致，参数全部取自 episode 的 HDF5：120 Hz、零阶保持、左臂 5 ms 和后臂 10 ms 的指令延迟、两臂驱动增益。夹爪按评测侧控制器直接跟随指令宽度（§4.3）。
- 渲染：`sim/render.py` 用 nvdiffrast CUDA 光栅化，再叠一个从成对图像学出的残差 U-Net（`sim/refine.py`，训练 `sim/train_refine.py`）。连杆位姿由 `sim/fk.py` 从 USD 关节算出，和 `observations/eef` 相差 0.01 mm。
- 驱动与评分：`sim/rollout.py`（单 episode），`sim/fleet_driver.py` 加 `scripts/fleet.sh`（每卡合批驱动，吞吐见 [throughput.md](throughput.md) §8），`sim/score.py`（按官方定义的本地 LHPR、TSR、ODR 和 reach@20），`sim/funnel.py`（操作漏斗），`sim/paired.py`（同 episode、同种子的配对比较）。
- 时长：本地 episode 不能短于 210 s，证据见 [throughput.md](throughput.md) §8。

### 4.2 为什么对不齐官方渲染

官方相机用 Isaac 的 RTX RaytracedLighting 渲染。在 H800 上，RTX 渲染第一帧就报 `ERROR_DEVICE_LOST` 后段错误退出，换 PathTracing、关抗锯齿、改 GPU 可见性都一样（`runs/logs/isaac_smoke*.log`）。驱动的 Vulkan 没有 `ray_query`，Isaac 的光追管线依赖硬件 RT 核 [H]。迁移目标集群的 B200 同样没有 RT 核。

与官方仿真的差距，从大到小：

1. 渲染。
2. 评测侧控制器，由 HDF5 attrs 反推，残差小。
3. 隐藏的测试布局和鲁棒 case，无从得知。
4. 接触混沌，只能统计对齐。

#### 4.3.1 task5 的积木几何（分支 phys-fidelity）[M]

原因不在求解器，在积木本身。HDF5 `sim` attrs 里有两项我们的 stage 没用上：

### 4.4 渲染差距与 refine

只用光栅时，渲染差距在大多数帧上不改变策略输出，但会改变"抓稳后开始抬"这一刻的决定。验证集里由后臂抓取的 12 个接触帧上只换 back_wrist 图：用录制图时 gripper_base 升高中位数 10.3 mm，用光栅图时只有 0.15 mm。这是一个二值决定。[M]

定位 [M]：把录制图底部中间两块（两指之间的积木）贴进光栅图，抬升就恢复。频段交换表明线索在 σ 2–16 px 的频段，内容是指尖附近积木的明暗：录制图里有接触暗区、暖色间接光和木纹浮雕，光栅图是灰色块状的直射阴影。整体亮度、机器人投影、自阴影和全局锐度都已排除。修阴影贴图、加法线和粗糙度贴图之后，12 帧里也只有 2–4 帧会抬，原因是环境光项表达不出 RTX 的方向性间接光。

对策是学一个残差网络：输入光栅 sRGB、G-buffer 和相机 one-hot，用同一状态的成对图像（光栅图与官方 JPEG）训练，只用训练集，验收全用验证集。它只改渲染器，不碰策略权重。v1（`runs/simdev/refine/v1/`）是小 U-Net，256² 随机裁剪，L1 损失，20000 步。v2（`runs/simdev/refine/v2/refine.pt`，`sim/rollout.py` 的默认）是 5 层 U-Net（32、64、128、256、256），640×480 整帧训练，拉普拉斯金字塔 L1，夹爪区域权重 ×2，30000 步。

#### 4.4.2 物理渲染（Mitsuba 3 路径追踪，已否决）[M]

官方 RaytracedLighting 在无 RT 核的 H800 上跑不了（§4.2），光传输可以用 Mitsuba 3 的 CUDA/OptiX 变体复现。`sim/pathtrace.py` 把 USDZ 的全部网格（不抽样，1,111,172 个三角形）、UsdPreviewSurface 材质（基色、粗糙度、法线贴图，principled BSDF）、工位唯一的 RectLight（900×600 mm，强度 3000，5600 K）和 HDF5 attrs 里的相机内参（OpenCV 针孔，主点用虚拟胶片裁剪实现，腕相机近裁剪 10 mm、外部 1 mm，外部相机旋转 180°）搬进去，4 路相机作为一个 batch sensor 一次发射。曝光和环境光项在 24 个训练状态上最小二乘拟合（曝光 1.59e-3，光栅 Look 用 1.93e-3；环境光相对灯面辐亮度 245）。逐通道增益剩余 R 0.98 / G 1.00 / B 1.04，逐相机增益在 10% 内，白平衡和曝光已对齐。分段线性检查显示录制图暗部比线性预测暗（最暗十分位比值 0.29，亮部 1.0–1.1），官方有未记录的色调曲线；按 64 档单调 LUT 拟合只把样本内 PSNR 从 20.6 提到 21.3 dB，不是主要残差。

结果见 §4.4.1 的表：未去噪时策略对蒙特卡洛噪声敏感（spp 1 差距 0.88 mrad）；OptiX 去噪后 spp 4 和 16 都是 0.34 mrad，与光栅的 0.39 同级，PSNR（16.9/22.4/22.5/24.5）和 VGG 距离也与光栅同级，离 refine v2 的 0.20 mrad 和 36 dB 很远。剩余差异是局部的：积木木纹颜色和浮雕（官方更暖、更饱和）、幕帘褶皱的明暗。降到 0.35 倍分辨率再放大，差距回到 0.51。

代价（GPU 2 与空闲策略服务器共用，357 个状态，每状态 4 路 640×480）：spp 1 去噪 0.23 s，spp 4 去噪 0.35 s，spp 16 去噪 0.45 s，spp 64 1.19 s；0.35 倍分辨率 0.19 s。每次发射有约 0.25 s 的 Dr.Jit 重追踪开销，所以 spp 1 不比 spp 16 便宜多少；`dr.freeze` 对顶点更新可以回放，但对腕相机回放成黑帧，没有采用。每材质共用一个 BSDF 对象是必要的（每网格各建一个会让每帧重追踪 9 s）。场景构建 3–4 s。

结论：光传输、曝光、白平衡都对齐之后仍只到光栅水平。官方帧与我们的差距在资产层面（纹理细节、材质响应）和未记录的后处理，不在光传输。refine v2 已在 0.20 mrad，贴着 0.19 的种子噪声下限，渲染保真不再投入。

### 6.1 关节跟踪滞后与插入高度（task5，分支 opt-t5）[M]

所有改动都在本地 train/val episode 上验证。

task5-3 的后臂滑行时，手中积木会比规划低。机理是速度相关的关节跟踪滞后。滞后量为 tau·qdot + coulomb·sign(qdot)，其中 tau = (kd + viscous)/kp 加上命令延迟（左臂 5 ms，后臂 10 ms）。kp、kd 和摩擦取自标定回读，所有示教里相同。后臂的 tau 是 j2 0.044、j4 0.106、j7 0.142 s，20 mm/s 滑行时手下沉 2–3 mm。本地不领先时的一段滑行（000015）实测 [−2.0, −2.6, −0.1, 11.0, −0.4, −1.6, −3.7] mrad，与模型逐关节吻合。本地塔冻结，积木卡住时塔不让位，所以本地看不到这个下沉的后果。左臂的竖直滞后只有约 0.1 mm。

改动（`sim/expert.py`，提交 263d8c8、5494e0e、4526821、77abe9e）：

1. 滑行段让关节领先它的预测滞后（`lag_lead`、`LAG`）。领先量投影到工具的竖直平移加转动上，不动水平分量（`Expert.lead_no_horizontal`）。不投影时，滑行开始那一下积木横向跳了约 1 mm（t5_new3_28：000015 第 1 次操作 lat 1.0 → 2.3 mm，000005/10/43 第 2 次操作 −0.3 → +0.5 mm）。槽每侧只有约 1 mm 间隙，这 4 条都卡在塔面上。投影后水平路径与不领先时相同。
2. `INSERT_DZ` 从 −0.2 改成 −0.3 mm。−0.2 是本地值，左臂竖直滞后约 0.1 mm，旧代码实际在 −0.3 滑行。领先后把这 0.1 mm 显式写进常数，task5-2 的实际滑行高度因此不变。
3. 坐实（insert-seat）只做一次。bb9a5d8 的特权专家在 task5-2 000057（偏移 0.015 −0.012 0.03）一直重复坐实，始终没有 done。
4. 试过又撤回：按两侧块实测高度滑行（task5-3 上 +0.7 mm）。3/13 的 task5-3 第 1 层失败（t5_new2_28），第 1 层积木撞到本地第 2 层积木：第 2 层积木在本地低 1.9 mm 并且倾斜，最低棱在 +14.5 mm。

诊断开关（只用于诊断，默认 0）：`JENGA_DIAG_INSERT_DZ_MM`（`sim/expert.py`）和 `JENGA_DIAG_TOWER_DZ_MM`（`sim/physics_worker.py`，平移冻结块的初始 z）。`Expert.rows_from` 新增可选参数 `lead`，默认关闭，task1–4 走的路径不变。

## 7. 渲染版 DART（已否决）

整数档 DART 只扰动状态 token，画面不变。有了渲染器，就能做画面与状态一致的扰动，让策略看到"手偏了"的样子。`sim/perturb.py` 生成了 `dart_v1`（已删除，r3b 用到的文件清单在 `runs/r3b/synthetic_files.txt`）[M]：

- 扰动：每帧每臂以 0.5 的概率把工具点平移 U(0, 20 mm)、旋转 U(0, 3°)，用 IK 求关节；夹住的积木随夹爪刚性移动；所有帧重新渲染。标签仍是示教的 `leader/qpos`，教的是"偏了就拉回示教"。
- 覆盖：475/475 条训练 episode，1,565,289 帧，339.3 GB，0 错误。
- 渲染用 refine v1（在 `perturb.py` 里固定）。未扰动帧对录制 JPEG 的 PSNR 按相机为 31.7 / 32.7 / 33.8 / 33.1 dB。
- 已知缺陷：没有碰撞处理，手和积木会穿进塔里；被推的积木不跟手。

r3b 混入 40% 后，离线大偏移恢复率明显提高（16 mrad 0.394 → 0.572），mae8 每个变体都退步，外部视角敏感度涨到 1.258 mrad（[evaluation.md](evaluation.md) §3.2）。本地闭环比 r3a 高 0.239 ± 0.043，r3d 证明这全部来自见过本地渲染画面（§5.2）。dart_v1 作为纠偏数据没有可测效果：标签只教"回到示教轨迹"，手和积木还会穿模。它唯一的结论是画面域差主导本地闭环分数。只有渲染器与官方对齐之后，这类合成数据在本地的收益才能外推到官方。

### 8.2 报告口径

演示里没有恢复片段（`sim/recovery_attempt` 全为 0），评测中出现的恢复只算偶然行为。DART 只覆盖几毫弧度的局部纠偏，单列为"小偏移纠正"，证据是恢复率。失败按类型标注：未抓稳、入口未对齐、执行停滞、稳定臂失配、物体滑移、结构破坏、阶段重复、块数错误、网络或超时，最后一类单独统计。组织方评测只用来验证候选，不用来生成训练数据。

## 9. 基座调研（已否决换基座）

冻结前继续用 π0.5。公开基准（如 RoboTwin 2.0 clean2random）的难度来自外观扰动，没有一个测过从 4 mm 的位姿覆盖外推到 15 mm、10° [P]；亚毫米接触的证据只来自仿真在线 RL（πRL [2510.25889](https://arxiv.org/abs/2510.25889)）[P]。最有希望的候选 LingBot-VLA 2.0（6B，自带连续状态，预训练含 AgileX 双臂）实际接入并全量微调过 [M]：24,450 步后在同一验证集上 mae8 为 1.368 mrad（10 步采样），约为同步数 π0.5 R1 的 1.7 倍、r2-40000 的 2.0 倍，夹爪误差约 5 倍；单次推理 701 ms，训练慢 3 倍。R2 相对 R1 的收益只有 18%，补不上 2 倍的差距，不再投入。相关代码、检查点和上游副本已删除，代码留在 git 历史里。

## 10. 风险与开放问题

专家与本地仿真：

- `sim/expert.py` 的 `INSERT_DZ` 是在本地拟合的：本地侧块比底座顶低 0.9 mm，官方 0.2 mm；task5-2 松手时的可行高度窗口只有约 ±0.3 mm（§4.3.1）。
- task5-3 只在冻结塔上通过。冻结低估屋顶被顶起时的让量，官方塔静止的真实碰撞覆盖层没有发布（§4.3）。
- task5-2 在本地 ODR 1.00，原因是本地屋顶下沉 1.6–2 mm，插入时被带走。官方示教里屋顶只动 0.3 mm，这项扣分可能是本地物理的伪像 [H]。
- 刚体偏移超过约 25 mm（官方范围是每轴 15 mm）时，task1 外侧第 1 层块的中心越过固定底座的棱，上层拿走后它自己掉下（distill pilot `runs/simdev/distill/pilot/s0` 的 80 条 task1：17 条失败里 14 条首帧有第 1 层块中心落在底座积木外包矩形之外 0.1–13.2 mm，63 条满分的没有一条如此；第 1 层块在 tick 770–2170 下落；本地 task1-2 000108 同理）。物理上无解，不改。
- 积木质量 2.0× 时搬运类任务掉块（§8.1）；官方指力设定未知。

早期微调策略线（r1–r3，不再推进，留作记录）：

- "放到了又丢掉"的机制：松手时机、放置位置，还是松手后积木滑落（§5.3）。
- r3a 的增益有多少来自接触加权，有多少只是多训了 4000 步（r3c 未完成）。
- r2 在官方画面下的真实闭环水平：本地 0.292 是在不熟悉的画面上测的，r3d 说明同一能力在熟悉的画面上是 0.576 量级。只有渲染器对齐（§4.4.1 的策略差）才能回答。
- DART 的纠偏为什么没有效果：标签太弱（回到示教而不是回到目标）、扰动与闭环失败形态不符，还是被画面效应淹没。
- v1 下的放置偏差和"不松手"分析没有在 v2 下重测（§5.4）。
- DAgger 没有跑通（§6.2）；专家偏移布局数据没有用于训练（§5.5）。
- 有了渲染器，训练期对整座积木做刚体平移的增强变得可做（原先的障碍是合成机械臂像素）[H]。
